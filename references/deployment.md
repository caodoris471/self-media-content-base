# WorkBuddy 接入与验收（原：{作者}）

## MVP 决策

沿用现有五张 Sheets；一个内容编排 skill（只服务{作者}）+ 一份角色配置 + WorkBuddy 原生助理入口 + 原生自动化。无需先迁移 Base，也无需先自建 n8n、云服务器或个人微信协议机器人。

本 skill 固定账号归属 = {作者}；多账号请各复制一份本底座独立部署，分别绑定各自的微信助手/会话；消息无需「{作者}」前缀。是否支持分享卡片自动提取 URL 仍需真实客户端验证。

飞书入库鉴权与微信入口是两件事；微信收到了任务不代表有飞书写权限。飞书自定义 webhook 通知机器人也不等于能接收用户转发任务的应用机器人。

## 微信助理 Bot（官方原生能力，2026-10-08 查证）

WorkBuddy **原生支持微信助理**，无需 AppID/AppSecret、无需自建服务器或协议机器人，扫码即绑。官方文档：https://www.workbuddy.cn/docs/workbuddy/WeixinBot-Guide

**接入步骤（需用户在 UI 完成扫码，Agent 无法代替）**：

1. WorkBuddy → 左侧「助理」栏 → 齿轮图标 →「助理设置」
2. 集成列表找到「微信助理集成」→ 点「配置」
3. 卡片下方出现二维码 → 手机微信扫码 → 状态变「已绑定」

**前置条件**：WorkBuddy ≥ 4.6.4 ｜ 手机微信 ≥ 8.0.70 ｜ WorkBuddy 与微信同一账号 ｜ 电脑保持开机且 WorkBuddy 运行中。

**支持的消息类型**：文字、图片、文件、语音（需微信语音转文字）。
✅ **已验证（2026-10-08 16:51）**：微信「分享卡片」能自动提取 URL。实测小红书分享卡片送达形态是纯文本分享文案，格式：
`【标题 - 作者 | 小红书 - 你的生活兴趣社区】 😆 口令 😆 https://www.xiaohongshu.com/discovery/item/<id>?...xsec_token=...`
含完整 xsec_token，**必须原样保留**（规范化仅用于判重，入库用原始链接）。
读取方式：`im_list_conversations` 被 Host policy 挡住 → 改读本地 `C:\Users\<你的用户名>\.workbuddy\projects\<项目>\<sessionId>.jsonl`，取 `role=='user'` 且剥掉 `<system-reminder>` 块后的正文。助理会话 cwd 是 `{助理工作目录}`（助理专属目录），不是普通任务目录。

**绑定后的执行链路**：微信消息 → WorkBuddy 助理会话（自动切到「助理」标签页）→ Agent 按本 skill 规则处理 → 写飞书 → 结果回传微信。

⚠️ **单会话约束**：一台电脑一对一绑定一个微信账号，助理只有一个会话。多个账号的 skill 共用同一个微信 Bot 时，各自约定触发前缀；本 skill 无前缀即按 {作者} 处理：
- 无前缀或「{作者}」开头 → 走本 skill（账号归属固定{作者}）

⚠️ **工作目录**：助理固定使用**助理专属文件夹**，与普通任务的自由工作目录不同。跨入口串联配置和账本必须用**绝对路径**。

## 先完成一次最小闭环

1. 在 WorkBuddy 导入本 skill，以及需要的 lark skills 完整目录。路径按实际安装位置定位；**博主视频全量扒取引擎已内置在本包 `扒取/` 子目录**，无需另装。
2. 检测 Python、FFmpeg、Whisper 模型、平台抓取依赖、lark-cli 和网络；沿用原 skill 的已验证平台方案。不要一开始升级或替换整套抓取引擎。
3. 角色已配置，读取 roles.md。识别现有对标表里哪些是视频主页、哪些是文章链接（⚙️ 先读表识别：哪些行是视频主页、哪些行是文章单篇链接）。
4. 先跑{作者}一条内容的实际读取、转写/正文提取、完整改写与飞书回读；再补视频在线抓取测试。用本地文章测试通过不能称为视频链路通过。只有相应链路通过，才推广到周任务。
5. 启用在线管理字段或可靠本地账本；先做同一链接重复投递测试，再开自动化。

## 🛑 第一闸门：先问后做（部署第一步，不许跳过）

**本 skill 是模板，不是成品。** 拿到它的人赛道、人设、表结构都不一样，所以**任何采集 / 改写 / 入库动作之前，必须先问、等填完、确认无误，才允许往下走。**

| # | 硬规则 |
|---|---|
| 1 | **一次性把「待确认清单」发全**，让用户一次填完；不许一条一条挤牙膏式追问 |
| 2 | **硬门槛（没填 = 不许继续）**：① 作者人设 / 账号归属 ② 内容赛道 / 主题方向。这两项决定人设、黑白名单、信源、栏目词表，缺了写出来的稿必然是别人的口气 |
| 3 | **填完复述一遍再动手**：作者是谁、赛道是什么、收什么剔什么、什么时候跑、写到哪张表。用户点头才开始执行 |

> ⚠️ 文档里的示例值只是告诉你"这里要填什么"，**不是默认值**。用户没答之前，任何采集 / 改写 / 入库都不许启动。

电脑需开机、联网、WorkBuddy 运行；长批次受宿主执行时限影响，应保存断点并续跑。Skill 是工作规则；触发时间由宿主调度，不会因复制 SKILL.md 自动开始运行。

## 验收用例

- 同一角色重复投递同一链接：不增加重复记录。
- 达标视频 12 条：必须交代 12 条各自状态，不只交付 3 条样稿。
- AND 阈值遇到播放量未知：登记待判定，不能算达标或当 0 丢弃。
- 中途停止/重启：续跑未完成阶段；写入超时先回读，避免重复行。
- 超长视频：完整逐字稿可在飞书打开，不能只显示本地路径或静默截断。
- 失败/登录失效：飞书或账本可看到具体原因，不标记“已完成”。
- 仅口播稿完成：发布状态仍为未发布，不自动标记已制作视频。
- 多账号各写各的表、各写各的角色稿：使用方的稿不能混进其他账号的语气或归属。

**本次落地的工程要点（写死，下次直接复用）**：

1. MediaCrawler 需先跑 `patch_extractor.py` 修 `extractor.py` 贪婪正则，否则主页解析直接失败（详见 `扒取/references/platform-xhs.md` 的 Patch 4）。
2. `--creator_id` 传**完整主页 URL**（带 xsec_token），传纯 ID 会丢鉴权参数。
3. Whisper：medium/small 在线下载失败 → 用 `HF_HUB_OFFLINE=1` + tiny + `local_files_only=True`（唯一稳定组合；large-v3 本地缓存仍不完整）。
4. lark-cli 写长文本：`--csv @file` 拒绝 allowlist 外路径，改用 `cat file | lark-cli ... --csv -`（stdin）。
5. `verify_rewrite_distinct.py` 会把 03/04 里**相同的 URL 元信息**误判为抄袭（LCS 59）→ 03 的元信息必须写成表格行（`|` 开头会被脚本排除）。
6. 04 文件名必须与 03 的 stem 完全一致（`001-标题.md`），否则脚本报「缺改写稿」。
7. 「完成情况」列是**下拉选项**（`support_multiple_values=true`，`enable_highlight=true`），共四项带色高亮：`已改成图文 #c3dd40`、`已改成视频 #ad82f7`、`已改成文章 #b1e8fc`、**`已改写待审核 #ff8800`（橙色）**。稿件生成阶段**统一打「已改写待审核」**（2026-10-09 用户指定），**不要写「纯文字稿」**——该值不在选项列表内，飞书不会给它上色，只会显示成普通文本。写值用 `+cells-set` 写 `value`（`+csv-put` 会吃中文首字）。
