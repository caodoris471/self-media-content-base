# 稿件自动化闭环：生成 → 自审 → 自动改 → 入库（2026-10-10 起全局生效）

适用：{作者}自媒体素材库**所有**产出链路（手动改写、批量改写、周采集、助理转发收录）。
**任何稿件在写进飞书之前，必须先过这道闸门。**

---

## 一、总流程（五步闭环）

```
① 生成初稿 MD
      ↓
② qa_check.py 规则闸门（确定性、零 Token）
      ↓ 有阻塞 → ③ LLM 审稿人按报告改稿
      ↓          （最多 2 轮；第 2 轮仍不过 → 标「受阻」，写原因进备注，不发布）
④ publish_row.py 推飞书 + 回写 H/K
      ↓
⑤ 抽审：每轮抽 2 篇人工核对，纠偏后回写本文件
```

**用户不需要逐篇盯**：只有「第 2 轮仍不过关」或「内容本身不足」的条目才会打扰人。

---

### 口播稿长度基准（2026-10-10 用户定）

**所有口播稿 ≈ 50 秒，220-280 中文字**（中文口播约 5 字/秒）。闸门阈值：`<180` 太短，`>340` 超时。
分段标记：`[Hook｜0-6 秒] / [痛点｜] / [转折｜] / [方法或实测｜] / [CTA｜45-50 秒]`。

### 轻量稿（图文/视频）长度上限（2026-10-10 用户追加：嫌太长）

🚫 **图文/视频不许出现「原文要点 / 原文文字稿 / 逐字稿」章节**，只要 **说明文字 + 口播稿** 两段。

| 类型 | 说明文字 | 口播稿 | 时长 |
|---|---|---|---|
| **图文** | **150-200 字** | **250-300 字** | 约 50-60 秒 |
| **视频** | **80-120 字** | **100-200 字** | 约 30-40 秒 |

> 2026-10-10 用户拍板：图文就是「**150 字说明 + 250 字口播**」，再长就不要。
> 视频更短的依据：画面已承载演示信息，说明只需点「抄哪个结构 + 一条落地提醒」；口播 30-40 秒完播率明显更好。
> 闸门命令 `--type koubo --sub img|video`（`--sub` 决定上限：img 说明 >200 或口播 >300 拦截；video 说明 >120 或口播 >200 拦截）。

## 二、先分流，再写（类型决定产出，不再每次问）

🔴 **2026-10-10 用户最终定稿**，覆盖此前所有版本：

| 类型（D 列） | 产出 | 逐字稿 | 长文稿 | 口播稿 | 说明文字 |
|---|---|---|---|---|---|
| **视频**（全部） | 只做口播稿 | ❌ 不做 | ❌ 不做 | ✅ | — |
| **图文** | 口播稿 + 说明文字 | — | ❌ 不做 | ✅ | ✅ |
| **文章**（非访谈） | 长文 + 短稿（口播稿） | — | ✅ | ✅ | — |
| **访谈**（不论类型） | **不动，跳过** | — | — | — | — |
| 文章 + 栏目=品牌剖析 | 五维品牌营销全景拆解模板 | — | ✅ | ✅ | — |

> 变更史：2026-10-10 曾一度误改成「图文不改写」并删掉 5 篇（第 13/15/20/24/27 行），当日已按新规则**重建**。以本表为准。

### 访谈怎么判（🔴 2026-10-10 用户再订正：**不许自动判，必须问**）

之前收录的条目**没有标「访谈」**，靠关键词猜必然会错。因此：

> **只要出现疑似访谈信号，一律停下来问用户，不许自己决定跳过，也不许自己决定照常改写。**

机检只负责**列出候选**，由用户拍板：

| 信号类型 | 候选特征（仅用于「提请你确认」） |
|---|---|
| 标题/备注显式带词 | 访谈、专访、对谈、对话、圆桌、播客、连线、聊了聊、答问 |
| 来源形态 | 喜马拉雅、小宇宙、Apple Podcast、圆桌派、播客节目 |
| 内容特征 | 两人以上一问一答、主办方提问 + 嘉宾长段回答、只有观点交锋没有独立方法论 |

**执行姿势**：批量跑到命中信号的那一行 → 把「行号 + 标题 + 命中信号」列给用户 → 等答复 → 再继续。**禁止**在用户没确认前替他跳过，也**禁止**替他判定"这不是访谈"。
确认是访谈后的动作：备注列写 `访谈类，不改写`，H/K 列留空。

## 三、规则闸门 qa_check.py

路径：本包 `scripts/qa_check.py`
运行（Python 3.12）：

```bash
"C:/Users/<你的用户名>/AppData/Local/Programs/Python/Python312/python.exe" \
  "<skill目录>/scripts/qa_check.py" <md路径> \
  --type article|koubo|brand [--json]
```

退出码：`0` 通过 / `1` 有阻塞级问题 / `2` 用法错。

### 检查项

| # | 检查 | 阈值 | 级别 |
|---|---|---|---|
| 1 | 章节完整性 | 缺任一段即阻塞 | block |
| 2 | 长文稿字数 | `<2200` 汉字（品牌剖析 `<2000`） | block |
| 3 | 视频/图文不得出现长文稿章节 | 出现即阻塞 | block |
| 4 | 口播稿字数（50 秒档） | `<180` 阻塞（太短）；`>340` 阻塞（超时）；`>300` 警告 | block / warn |
| 5 | 引流广告词 | 出现即阻塞（**原文段内的不算**） | block |
| 6 | 中英混杂 | 白名单外英文词：普通稿 >8 阻塞；品牌稿 >40 阻塞（品牌名/人名多） | block / warn |
| 7 | Hook / CTA 分段标记 | 缺 `[Hook｜x-y 秒]` 或 `[CTA｜]` 必缺一不可 | block |
| 8 | CTA 可执行 | 结尾 260 字内需含「今晚/评论区/跑一遍/动手」等具体动作词 | warn |
| 9 | **改写度**（防洗稿） | 长文 vs 原文 4-gram 重叠 >30% 阻塞，>20% 警告 | block / warn |
| 10 | 原文段网页导航垃圾残留 | 出现即提示 | warn |
| 11 | 一级标题存在且等于原标题 | 缺失阻塞 | block |

`--json` 输出结构化 issues（level: block/warn/info），供自动改稿环节消费。

---

## 四、改稿人环节（LLM）

阻塞项就是修改清单，不要靠人肉挑：

1. 拿 `--json` 的 `blocks` 逐条改，改完再跑一次闸门；
2. **最多自动改 2 轮**；第 2 轮还有阻塞 → **不发布**，把这一行在表格备注列写「受阻：<原因>」，K 列**不打标签**，交给人；
3. 警告项尽量顺手清掉，但不卡发布。

## 五、发布

```bash
cd "C:/Users/<你的用户名>/AppData/Local/Temp/news_raw"
"C:/Users/<你的用户名>/AppData/Local/Programs/Python/Python312/python.exe" \
  publish_row.py <row> "<原标题>" "<md绝对路径>"
```

内部：知识库父节点 `{知识库父节点token}` 建文档 → 写内容 → 回写 `H{row}`（文档卡片 mention）+ `K{row}` = `已改写待审核`（橙 `#ff8800`）。

## 六、每日 PDO 扫描（09:30）

每天 09:30 自动扫 `{素材表ID}`：

1. **先补标签**：助理收录行（B 列=⚙️{作者}、由自动化写入）若 `I 列` 为空或非「符合」，先统一补成「符合」（2026-10-10 用户定稿：助理收录的一律符合，不做内容筛选）；
2. **再找待办**：`I 列 = 符合` 且 `H 列为空` 的行，按类型分流走上面闭环；
3. **J 列（迫切程度）一律不动**，不读不写，由用户手动打。

只有「第 2 轮仍不过闸」或「素材本身不足」的条目才汇报给用户，其余静默入库。

- 阈值、词表、类型分流只改本文件 + `qa_check.py` 的 `WHITELIST` / `AD_WORDS` / `NAV_GARBAGE` 常量；

- 每次用户纠偏后，把新规则回填到本文件和 `references/sop.md`，否则下一次又会按旧版本执行。
