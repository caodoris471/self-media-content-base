## 📖 项目简介

把收藏夹里的链接、对标博主的视频和行业资讯，整理成有来源、有人设、有处理状态的素材与稿件，统一写入飞书，方便继续选题、审核和制作。

这是一套可按账号配置的 **AI 工作流模板**，包含执行规则、角色配置、采集脚本和部署说明。现有部署文档以 **WorkBuddy + Windows + 飞书工具** 为基础；首次使用需要填写人设、赛道、信源和目标表格，完成授权及小样本验收。

### 能帮谁

- **持续做内容的个人创作者**：收藏了很多好内容，真正写稿时却找不到；希望把日常收集变成自己的选题和口播草稿。
- **负责多个栏目的内容运营**：每天要追资讯、研究对标、整理素材，手动登记表格和跟进稿件状态占用大量时间。
- **有固定人设与审核流程的小团队**：需要让素材、逐字稿、改写稿和进度对应起来，减少不同成员之间重复整理和漏交付。

### 解决什么问题

| 以前 | 现在 |
|---|---|
| 链接散在微信、收藏夹和聊天记录里 | 按规则提取内容、分类登记，保留原始来源 |
| 研究对标要逐条听写，再重新写口播 | 内置采集与转写流程，由 AI 读原稿后按人设重新组织表达 |
| 每次写稿都要重新解释账号定位 | 一次配置人设、栏目、选题规则与稿件格式，后续复用 |
| 资讯只是标题堆积，不知道能做什么内容 | 核对原文与时间，整理选题方向，按已启用策略生成文字稿或口播稿 |
| 表格里有记录，却不知道稿件做到了哪一步 | 关联素材、文稿和处理状态，写入后回读检查 |

### 🔧 原理

链接 / 博主名单 / 资讯信源 → Agent 读取规则与角色配置 → 提取正文或调用内置视频采集引擎 → 必要时用 faster-whisper 本地转写 → AI 按人设改写 → 质检 → 写入飞书电子表格与文档并回读。素材采集和转写依赖本机工具；模型写作使用宿主 Agent，不要求单独购买转写 API，但宿主模型、网络或第三方服务可能另有费用。

## ✨ 功能特性

| 环节 | 功能 | 状态 |
|---|---|---|
| 日常收集 | 单篇链接 / 已提供正文 → 内容提取、分类、改写、素材表登记 | ✅ 按来源可访问性执行 |
| 对标研究 | 博主名单 → 按时间与互动指标筛选 → 下载、逐字稿、改写稿 | ✅ 内置采集引擎 |
| 资讯整理 | 配置信源 → 核对原文和发布时间 → 提炼选题与稿件 | ✅ 由 Agent 与脚本配合执行 |
| 账号定制 | 配置人设、赛道、栏目、黑白名单、语气与稿件格式 | ✅ 首次部署需填写 |
| 飞书入库 | 素材、逐字稿、改写稿、文档链接与处理状态对应登记 | ✅ 需授权和字段映射 |
| 微信入口 / 定时运行 | 从微信助理接任务，或由宿主自动化按计划触发 | 🚧 需单独接入、配置与验收 |

**三条工作流与交付结果：**

| 你提供什么 | 它帮你完成什么 | 结果放哪里 |
|---|---|---|
| 一条内容链接或正文 | 原文提取、栏目分类、按人设改写 | 飞书素材表；长稿按配置关联文档 |
| 对标博主主页或已配置名单 | 视频清单、源文件、带时间轴逐字稿、独立改写稿 | 本地任务目录 + 飞书对标结果表 |
| 已配置的行业信源与时间范围 | 带来源的资讯、选题方向，以及按策略生成的文字稿 / 口播稿 | 飞书资讯表与关联文档 |

**平台分工：**

| 类型 | 范围 | 使用条件 |
|---|---|---|
| 视频采集来源 | 视频号、小红书、抖音、B站、快手、YouTube、TikTok、Instagram | 来自内置引擎的 8 平台流程，先检查当前登录、网络和可达性 |
| 单篇素材 / 资讯来源 | 小红书笔记、公众号文章、可访问网页、已配置行业信源 | 按实际正文提取能力处理；不可读取时可提供正文 |
| Agent 执行宿主 | 现有部署文档为 WorkBuddy；Codex / Claude Code 需适配工具 | 能读取 Skill、执行本地命令、调用浏览器和飞书工具 |
| 输入入口与存储 | 宿主聊天；配置后的微信助理；飞书 Sheets、文档与知识库 | 微信接入和飞书授权分别配置 |

八平台验证记录来自内置引擎 **2026 年 9 月的历史案例**，不代表本次重新验证了全部链路，也不保证任意账号都能完整采集。筛选以平台实际返回的字段为准；缺失的播放量等指标不能当作 0。现有飞书字段方案使用 **电子表格 Sheets**，迁移到多维表格 Base 需要另做适配。

### 方式一：一句话安装（推荐）

把下面这段发给你使用的 Agent。安装到 Codex / Claude Code 后，应先检查工具适配；现有 WorkBuddy 的微信助理与自动化配置不能直接当作其他宿主的现成功能。

```text
帮我从 GitHub 安装这个 Skill：
https://github.com/caodoris471/self-media-content-base
按当前宿主克隆完整仓库：
Codex：~/.codex/skills/self-media-content-base
Claude Code：~/.claude/skills/self-media-content-base
WorkBuddy：~/.workbuddy/skills/self-media-content-base
先检查目标目录是否已有修改，不覆盖现有定制版。
读取 SKILL.md、references/deployment.md 和 SOP流程说明-底座版.html。
确认 scripts/、references/、扒取/ 齐全，采集引擎已内置，不重复安装。
本仓库没有统一安装脚本，请按目标工作流检查依赖和宿主工具。
先一次性列出我需要填写的人设、赛道、信源、筛选规则和飞书配置，
填好并确认后，再完成授权与一条内容的提取、改写、入库和回读测试。
```

装完说的第一句话：

```text
使用 self-media-content-base，帮我配置一个自己的自媒体素材库。
先发完整配置清单，确认我的人设、内容赛道和飞书目标位置。
配置完成后，用我提供的一条链接验证“提取 → 改写 → 入库 → 回读”。
```

部署验收通过后，可以这样下任务：

```text
使用 self-media-content-base：整理这条链接 <内容链接>，
按已配置人设生成口播稿，登记到我的素材表，返回来源和稿件位置。
```

```text
使用 self-media-content-base：研究这个抖音博主 <主页链接>，
筛选最近 30 天点赞超过 1000 的视频，按干货拆解型改写，写入对标结果表。
```

```text
使用 self-media-content-base：更新已配置信源最近 7 天的行业资讯，
核对原文、日期和重复事件，提炼适合我账号的选题，按已启用策略入库。
```

开工前会核对人设、赛道、稿件要求、采集范围和飞书目标；已确认的配置可以复用，新增或缺失的关键项再补齐。

### 方式二：手动安装

以下为 Codex 的 PowerShell 示例；Claude Code 将 `.codex` 替换成 `.claude`，WorkBuddy 替换成 `.workbuddy`。目录已经存在时先检查，不覆盖定制内容。

```powershell
$skillPath = Join-Path $env:USERPROFILE '.codex\skills\self-media-content-base'
git clone https://github.com/caodoris471/self-media-content-base.git "$skillPath"
Set-Location -LiteralPath $skillPath
Get-Content -LiteralPath '.\SKILL.md' -Encoding UTF8
# 没有统一安装脚本：让 Agent 按下表检查依赖，再配置人设与飞书。
# 下载后可用浏览器打开 SOP流程说明-底座版.html 查看部署步骤。
```

连接 GitHub 失败时，先确认本机网络和实际代理配置。详细安装使用现有 [SOP 页面](SOP流程说明-底座版.html)、[接入与验收](references/deployment.md) 和 [使用说明](使用说明.md)，本仓库目前没有单独的 `docs/` 目录。

## ⚙️ 需要换成你自己的

先保留一份模板，为自己的账号创建定制副本；不同账号分别绑定人设和目标表。仅修改本次工作流实际使用的配置与脚本。

| 文件 | 字段 | 填什么 |
|---|---|---|
| `SKILL.md`、`references/roles.md` | 作者、账号归属、人设、语气与内容赛道 | 你是谁、为谁写、关注什么、如何表达 |
| `SKILL.md`、`references/sop.md`、SOP 页面 | 栏目、信源、选题黑白名单、时间窗与热度阈值 | 自己的内容规则，不直接采用示例值 |
| `references/schema.md`、入库脚本 | 表格、工作表、知识库位置、字段映射与工具路径 | 自己有权读写的飞书目标与工具；不要提交凭据 |
| `scripts/publish_*.py` 等实际调用的脚本 | 工作目录、表格坐标、文档位置、目标域名等占位或示例常量 | 当前项目的真实配置；先检查再执行 |
| `扒取/scripts/` 中实际调用的脚本 | 项目目录、源数据路径、模型与语言 | 本次任务目录、可用模型和视频实际语言 |
| 宿主的入口与自动化配置（按需） | 微信绑定、执行时间、时区、配置与账本路径 | 自己的接入和计划；复制 Skill 不会自动创建任务 |

## 🗺️ 完整流程

| # | 节点 | 工具 |
|---|---|---|
| 1 | 确认作者、赛道、信源、稿件要求和目标表 | Agent + 配置清单 |
| 2 | 检查依赖，完成登录与飞书授权 | 本机环境 + 采集 / 飞书工具 |
| 3 | 用一条实际内容验证提取、改写、入库和回读 | Agent + 对应工作流 |
| 4 | 接收链接、读取对标名单或执行资讯任务 | 宿主聊天 / 已配置入口 |
| 5 | 提取正文，或采集视频并完整转写 | 浏览器 / 内置引擎 + Whisper |
| 6 | 保留来源，分类并按人设生成稿件 | Agent + 角色与稿件规则 |
| 7 | 检查格式、完整性、事实与改写差异 | 质检规则 + 对应检查脚本 |
| 8 | 写飞书并回读，记录各条状态与失败原因 | 飞书工具 + 任务账本 |
| 9 | 基础链路通过后，按需配置微信入口或自动化 | 宿主提供的接入与调度能力 |

详细 SOP 见 [SOP 页面](SOP流程说明-底座版.html)、[全流程说明](00-SOP-自媒体素材库全流程.md) 和 [接入与验收](references/deployment.md)。视频任务应单独验证实际视频链路；文章测试通过不代表全部平台均已通过。生成稿件后标记待审核，制作与发布状态按真实进度登记。

## ❓ 常见问题

- **装完为什么没有自动开始收素材？** 先完成人设、赛道、飞书配置和一条内容的闭环验证；微信助理和定时任务还需在宿主中接入。
- **Codex / Claude Code 能直接照搬微信和定时配置吗？** 现有接入说明针对 WorkBuddy。其他宿主需要映射命令、浏览器、飞书权限和调度能力，并重新验收。
- **公众号或某个平台链接读不到？** 检查登录与访问条件，无法取得正文时提供原文；不要根据标题编造完整内容。八平台视频流程也受权限、网络和限流影响。
- **飞书能读却不能写，或者长稿不完整？** 分别检查写权限、工作表字段和文档位置；用一条内容做写入回读，长稿按配置关联可打开的文档。
- **为什么改写稿只是原文换词，或者任务中途停止？** 前者需由 AI 重新组织并通过相应质检；后者应查看账本中的实际阶段，核对远端结果后续跑，避免重复入库。
- **与 blogger-video-pipeline 怎么选？** 只需要一次对标研究和本地视频 / 逐字稿，选 [blogger-video-pipeline](https://github.com/caodoris471/blogger-video-pipeline)。需要持续收集、按人设改写和飞书协作，选本仓库；采集引擎已内置。视频剪辑与社交平台发布需另用对应工具。
